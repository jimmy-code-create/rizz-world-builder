PHASE 1 - BACKEND AS SQL (folder backend-sql/)
Rules for every file: idempotent and re-runnable (create ... if not
exists, create or replace function, drop policy if exists before create),
wrapped in begin/commit, RLS enabled on every new table, SECURITY DEFINER
functions use set search_path = public with revoke all from public and
grant execute to authenticated only, no data loss, no column renames or
drops, and end with notify pgrst, 'reload schema'. Each file begins with a
comment saying what it does and ends with commented verification queries
and a rollback note.
00_audit.sql: read-only queries listing tables, columns, policies,
 functions, triggers and realtime publications (so I can paste the output
 back when something breaks).
01_group_invites.sql: invite codes with expiry, max_uses, uses, revoked_at.
 RPC get_group_invite_preview(_code) (name, avatar, member_count; callable
 by anon and authenticated). RPC accept_group_invite(_code text) returning
 the group id: validates the code, rejects blocked users and existing
 members, enforces friends-only (mutual follow with at least one member),
 inserts the member, increments uses. Stable error codes via raise
 exception: invalid, expired, revoked, already_member, not_friends,
 blocked. Admin RPCs to create and revoke invites.
02_blocks.sql: blocks with insert and delete policies for the blocker,
 unique (blocker_id, blocked_id), index, helper is_blocked(a, b). Messages,
 invites, calls and story visibility respect it.
03_group_messages.sql: members-only SELECT and INSERT RLS, realtime enabled,
 index (group_id, created_at desc), reply_to_id, edited_at, deleted_at, and
 a message_deletions table for "delete for me" vs "for everyone".
04_reactions_counts.sql: unique (user_id, target_id) on likes; like and
 comment counters kept by triggers or RPCs that return the true count;
 message reactions table; index on comments(post_id).
05_stories.sql: story_views, story_reactions (unique per user per story),
 an RPC that sends a story reply into a DM, audience rules reuse
 close_friends, 24h expiry via a view or filter.
06_calls.sql: calls (id, conversation_type dm|group, conversation_id,
 caller_id, kind audio|video, status ringing|active|ended|missed|declined,
 created_at, answered_at, ended_at) and call_participants (call_id,
 user_id, state invited|joined|left|declined). RLS: only participants read,
 only the caller inserts, users update only their own participant row.
 RPCs start_call, join_call, decline_call, end_call. A function marks
 ringing calls older than 45s as missed and inserts a "Missed call"
 message. Block rules apply. Realtime enabled. Signaling uses Realtime
 Broadcast on channel call:{id}; if private channels are used, add RLS on
 realtime.messages so only participants can send or receive.
07_chat_stories.sql: chat_stories (id, author_id, title, hook, language,
 cover_url, characters jsonb, status draft|published, created_at),
 chat_story_chapters (story_id, idx, title, data jsonb, unique
 (story_id, idx)), chat_story_progress (user_id, story_id, chapter_idx,
 scene_id, speed, updated_at), chat_story_reactions. RLS: published stories
 readable by everyone, authors manage their own, each user manages their
 own progress.
08_storage.sql: buckets chat-media, story-media, story-audio with policies
 (public read for story-audio, owner write; chat-media only for
 conversation members), size and mime limits.
09_indexes.sql: indexes for every hot path (messages, notifications,
 follows, stories by expires_at, reels feed).
README.md: the exact run order, what to expect, and verification queries.

PHASE 2 - WORKER (folder worker/, Cloudflare, free)
A Worker (wrangler.jsonc + src/index.ts) that returns short-lived TURN
credentials. It verifies the user's Supabase JWT, limits CORS to my
frontend origin, rate-limits per user, and reads secrets only from
wrangler secrets. The frontend uses VITE_WORKER_URL. Document the free
TURN option and setup in worker/README.md. Skip Web Push.

PHASE 9 - CALLS (PC-PC, mobile-mobile, PC-mobile, mobile-PC)
- Remove any userAgent/isMobile branching that blocks combinations.
- Handshake: caller sends "ring", callee accepts and subscribes, callee
  sends "ready", then the caller creates the offer. Perfect negotiation,
  ICE candidate queue, trickle ICE, ICE restart on failure, "Reconnecting"
  and poor-connection indicators.
- ICE: STUN + TURN (udp, tcp, tls 443) with credentials from the Worker.
  If TURN is missing, show a clear error.
- Video: prefer VP8, H264 fallback; mobile 540p ~800kbps, desktop 720p.
- Audio: echoCancellation, noiseSuppression, autoGainControl all true, plus
  an "Enhanced noise cancellation" toggle (RNNoise WASM in an AudioWorklet,
  safe fallback). Fix "I cannot hear you": remote stream on an <audio
  autoplay playsinline> element, resume AudioContext on a gesture, and a
  "Tap to enable sound" button if play() is blocked.
- Controls: mute, speaker, camera, flip, end, audio level meter. Wake Lock
  during calls.
- Not in the app: full-screen incoming sheet on mobile, top banner on
  desktop, ringtone (vibration fallback), Accept/Decline, 45s timeout.
  "Call in progress - Join" pill in the chat header, DM list and group
  header. Deep link /call/:id (login first, then return). Missed calls
  appear in the chat with a "Call back" button.
